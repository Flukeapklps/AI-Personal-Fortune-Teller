# Personal AI Fortune Teller (ดูดวง)

A personal horoscope web app (Next.js 16, TypeScript, Tailwind CSS v4, Supabase, Claude API).
Users enter only their **date of birth** and pick the life areas and time period they want a reading for. They get a personalised Thai horoscope with luck scores, lucky details, history, favourites and comparisons.

> Predictions are for entertainment and personal reflection only. Scores are illustrative ratings, not measured probabilities.

## Quick start

```bash
npm install
cp .env.example .env.local   # fill in Supabase + ANTHROPIC_API_KEY
npm run dev                  # http://localhost:3000/fortune
npm test                     # unit tests (dates, zodiac, CNY, numerology, scoring, cache keys)
```

**Live demo (GitHub Pages):** https://flukeapklps.github.io/AI-Personal-Fortune-Teller/fortune/

**Demo mode:** without Supabase env vars (non-production only), the app uses an in-memory store and a single demo user, so the module can be tried immediately.
Without `ANTHROPIC_API_KEY`, readings come from the built-in fallback generator.

## GitHub Pages (static build)

GitHub Pages only serves static files. So `npm run build:static` builds a static version of the site (into `out/`):

- No API routes, proxy or login. The Fortune Teller runs entirely in the browser.
- Birth profile and history are stored in the visitor's `localStorage`, and readings use the offline generator. The Claude API key is never exposed, so Claude isn't called.
- Dates, zodiac, numerology, scoring, caching, favourites and compare work the same way as the full version.

`.github/workflows/deploy-pages.yml` runs tests, builds and deploys on every push to `main` (or manually via *Run workflow*).
One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

For the full version (Supabase + Claude), deploy the normal build (`npm run build`) to a Node host such as Vercel.

## Database

Apply `supabase/migrations/20261107000000_fortune_teller.sql` (e.g. `supabase db push`). It creates:

| Table | Purpose | RLS |
|---|---|---|
| `horoscope_categories` | Lookup: education / career / love / finance | read for signed-in users |
| `user_birth_profiles` | One row per user: birth date, optional nickname, timezone | owner only |
| `horoscope_predictions` | History + cache (`cache_key`, `variant`, JSON `content`) | owner select/insert/delete; immutable |
| `horoscope_favorites` | Saved favourites | owner only; must own the prediction |

### Calculation notes

- **Periods** (today = 7 Nov 2026): *Today* = 7 Nov. *Next N days* start tomorrow (7 days = 8–14 Nov; 30 days = 8 Nov – 7 Dec). *Next N months* start tomorrow and end the day before the same date N months later (12 months = 8 Nov 2026 – 7 Nov 2027). *Next calendar year* = 1 Jan – 31 Dec 2027. "Today" is taken in the user's browser timezone (sent with each request, default `Asia/Bangkok`).
- **Chinese zodiac:** compares the birth date with that year's Chinese New Year. The 1900–2100 date table is generated by `scripts/generate-cny-table.mjs` from `lunar-javascript`. ICU's `Intl` Chinese calendar is *not* used for the table: it gets 1954, 2027 and 2030 wrong by a day.
- **Life Path Number:** reduce day, month and the 4-digit year separately (keeping masters 11/22/33), add them, then reduce again. Example: 29 Nov 1990 → 11 + 11 + 1 = 23 → **5**.
- **Scores** are seeded from birth date + period + range + variant. The same request always gives the same numbers, and Claude writes text that matches them. Bands: 90–100 ดีเยี่ยม, 80–89 ดีมาก, 70–79 ดี, 60–69 ปานกลาง, < 60 ควรระมัดระวัง.
- **Caching:** key = `userId | birthDate | categories | period | rangeStart_rangeEnd`. Refreshing reuses the stored reading. *ขอคำทำนายใหม่* stores a new `variant`.
